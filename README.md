# SANKET (संकेत)

*"the sign that comes before"*

SANKET is a national glacial-hazard early-warning system for Nepal: a standing watch that
looks, decides, explains and acts on its own, and stops at a named human district officer
before anything reaches the public. See [`SOLUTION_SHEET.md`](SOLUTION_SHEET.md) for the
one-page summary, [`01-PRODUCT-SPEC.md`](01-PRODUCT-SPEC.md) for the full product case, and
[`04-AGENT-REFERENCE.md`](04-AGENT-REFERENCE.md) for how the six agents work.

## Running it

```
uv pip install --python .venv/bin/python3 -e ".[dev]"
cp .env.example .env   # fill in HACKATHON_KEY, GROQ_KEY, EARTHDATA_USERNAME/PASSWORD, etc.
sanket                 # starts the live daemon (watch.daemon:main)
flask --app api.app run     # the board's API
cd board && npm run dev     # the board itself
```

`pytest -q -m "not network"` runs the non-network suite. `pytest -q` runs everything,
including tests that call real providers and real public data sources.

## The MCP server

```
uv pip install --python .venv/bin/python3 -e .
sanket-mcp
```

Exposes SANKET's own 12 deterministic Investigator tools (`search_granules`,
`detect_water_change`, `detect_disturbance`, `lake_area_series`, `precip_percentile`,
`stage_volume`, `breach_hydrograph`, `route_flood`, `exposure_at`, `precedent`,
`science_lookup`, `write_status`) over the Model Context Protocol, so another agent can call
the same physics and satellite tools SANKET's own Investigator uses. `write_status` through
this server writes to an isolated demo board, never the live one.

## Honest numbers

`notebooks/06_calibration.ipynb` calibrates our own solver against `geo-pera`'s independent
reconstruction and reports the residual as measured, not adjusted: modelled median depth
11.6 m against a reported ~70 m, roughly -83%, with the physical reason stated plainly (a
water-only shallow-water model cannot reproduce a rock-ice avalanche's direct momentum
entry into the channel). `notebooks/07_validation.ipynb` reports confusion matrix, IoU,
precision and recall against both CEMS EMSR927 and the HDX flood-extent reference at two
scenario volumes — recall against EMSR927 is 0.15–0.19, reported without softening.

## What is mocked, declared

See the "Blunt real-vs-mocked list" in [`SOLUTION_SHEET.md`](SOLUTION_SHEET.md). In short:
the institutional contact table (beyond the district officer's own number), SMS sending,
and the voice call's phone dial-out are simulated and declared as such in code
(`synthetic=True`, `SIMULATED_GATEWAY`, `dialler_simulated=True`); the replay clock
simulates elapsed time only, over entirely real granules, DEM reads and solver output; the
`sanket-plan-local` Ollama rung was evaluated and dropped rather than shipped unrunnable.

## Contributing

Issues and pull requests are welcome. Once this repository has a public remote, open an
issue to propose a change before a large PR — in particular anything touching
`agent/router.py`'s provider contract, the Verifier's veto policy, or the gate in
`actions/gate.py`, since those are the system's safety boundaries.

## Layout

`core/` — config, state, provenance envelope, corridor/contact registries. `analysis/` —
EO detection, hydraulics, exposure. `agent/` — the six-agent loop, router, RAG, sandbox.
`watch/` — the daemon, tiering, the live investigation queue and worker, replay. `actions/`
— the gate, channels, the autonomous/gated split. `api/` — the board's Flask API. `board/`
— the Next.js board. `sanket_mcp/` — the published MCP server. `notebooks/` — the analysis
notebooks referenced above. See [`PROGRESS.md`](PROGRESS.md) for the full phase-by-phase
build log and [`progress.json`](progress.json) for the machine-readable version, including
every architectural decision made along the way.
